## Objective

Day 24 delivers the operator stop-disable flow and the booking passenger actions it creates, including deterministic deadline fallback. It also closes the no-show state machine for passengers who remain pending after a stop or terminal departure, and publishes the notification facts required by downstream consumers. The work must preserve Day 23 current-departure, idempotency, tenant, refund, and Outbox invariants. Day 25 is the independent ParcelRouteFare/Create-parcel scope; this plan claims no operational-reporting dependency for it.

## Success criteria (DoD — binary, verifiable)

- [ ] Disabling a stop creates `BookingPendingAction` records for every eligible confirmed booking, with the ratified deadline and metadata, and never creates a duplicate active action.
- [ ] A passenger can select a replacement stop, accept the terminal fallback, or cancel with a 100% STOP_DISABLED refund; replaying the same mutation is idempotent and a stale/late action cannot be accepted.
- [ ] Unresolved stop-disabled actions are deterministically resolved at the deadline to the ratified terminal fallback and notify the passenger.
- [ ] A confirmed passenger still `PENDING` is marked `NO_SHOW` only when the along-route anchor satisfies `TripStop.actualArrivalTime + 15 minutes < now`, or the terminal anchor satisfies `Trip.actualDepartureTime + 15 minutes < now`; equality is excluded. Mixed `BOARDED`/`NO_SHOW` bookings become `PARTIAL_NO_SHOW` and all-pending bookings become `NO_SHOW`.
- [ ] Stop-disabled, fallback, passenger no-show, and stop-departed-with-pending facts have the ratified routing keys, Outbox identity, and consumer behavior; the 3/5 and 5/5 boarded cases are covered by executable evidence.

### Human-ratified addenda (2026-07-18; canonical)

These addenda close the prior pending-count and depart-lifecycle blockers without renumbering or altering D24-1–D24-6. Task 24.0 must freeze them field-for-field in the API/SOT/error/job registries before Tasks 24.7 or 24.8 run.

1. **Addendum A — Pending-count contract.** Booking counts exactly Passenger rows whose parent `Booking.status = CONFIRMED`, `Passenger.boardingStatus = PENDING`, `Booking.tripId = tripId`, `Booking.pickupStopId = stopId`, and `Booking.operatorId = operatorId`. No matching row returns raw `200 { tripId, stopId, pendingPassengerCount: 0 }`. The sole caller rule is a valid Internal JWT; an invalid token returns `401 AUTH_TOKEN_INVALID`. Empty/all-zero or malformed `tripId`, `stopId`, or `operatorId` returns `422 VALIDATION_ERROR`. There is no Trip/Stop lookup, caller-service/tenant-claim authorization, or extra cross-service validation seam, and absent logical Trip/Stop/operator references never produce `403`/`404`; Trip validates its own trip, stop, assigned crew, and tenant before it calls Booking.
2. **Addendum B — Driver stop-depart lifecycle.** First execution is allowed only when `Trip.status = IN_PROGRESS`, `TripStop.status = ARRIVED`, and `TripStop.actualDepartureTime IS NULL`. A Trip outside `IN_PROGRESS` returns existing `422 TRIP_NOT_IN_PROGRESS`; a `PENDING` or `SKIPPED` stop returns new `422 TRIP_STOP_NOT_ARRIVED`; a valid new idempotency key after departure returns new `409 TRIP_STOP_ALREADY_DEPARTED`. The same key plus the same fingerprint replays the original HTTP status and response bytes before current-state lookup; the same key plus a different fingerprint returns `422 IDEMPOTENCY_KEY_MISMATCH`. A Trip/TripStop row lock or equivalent CAS permits one winner to persist the timestamp and, only for a positive count, one event; a race loser/new-key conflict persists and emits nothing. Focused equality/replay, mismatch, state-matrix, race, Outbox identity, publisher-restart, and no-extra-event tests are mandatory.

function Invoke-Day24Trx([string]$Project,[string]$Fqn,[string]$Name) {
  $d=Join-Path ([IO.Path]::GetTempPath()) ("vr24-$Name-"+[guid]::NewGuid())
  dotnet test $Project -c Release --filter "FullyQualifiedName~$Fqn" --logger "trx;LogFileName=$Name.trx" --results-directory $d
  if ($LASTEXITCODE -ne 0) { throw "$Fqn failed" }
  $trx=(Get-ChildItem $d -Filter "$Name.trx" -Recurse | Select-Object -First 1).FullName
  if (-not $trx) { throw "$Fqn produced no TRX" }
  [xml]$x=Get-Content $trx
  $c=$x.SelectSingleNode("/*[local-name()='TestRun']/*[local-name()='ResultSummary']/*[local-name()='Counters']")
  if ([int]$c.executed -lt 1 -or [int]$c.passed -lt 1 -or [int]$c.failed -ne 0 -or [int]$c.error -ne 0 -or [int]$c.timeout -ne 0 -or [int]$c.aborted -ne 0 -or [int]$c.notExecuted -ne 0) { throw "$Fqn executed zero or had failures/skips" }
}
function Get-Day24ChangedFiles([string[]]$Roots) {
  $files=@()
  foreach($root in $Roots) {
    if(Test-Path -LiteralPath $root -PathType Leaf) { $files += (Resolve-Path -LiteralPath $root).Path }
    elseif(Test-Path -LiteralPath $root -PathType Container) { $files += Get-ChildItem -LiteralPath $root -Recurse -File | Where-Object { $_.Extension -in '.cs','.csproj','.ts','.tsx','.js','.json' } | Select-Object -ExpandProperty FullName }
    else { throw "Day24 verification root does not exist: $root" }
  }
  if($files.Count -lt 1) { throw 'Day24 verification selected zero changed-file roots' }
  return $files
}
function Assert-Day24Lf([string[]]$Roots) {
  $files=@()
  foreach($root in $Roots) {
    if(Test-Path -LiteralPath $root -PathType Leaf) { $files += (Resolve-Path -LiteralPath $root).Path }
    elseif(Test-Path -LiteralPath $root -PathType Container) { $files += Get-ChildItem -LiteralPath $root -Recurse -File | Where-Object { $_.Extension -in '.ts','.tsx','.js','.json','.md','.yml','.yaml','.sh','.prisma','.sql' } | Select-Object -ExpandProperty FullName }
    else { throw "Day24 LF root does not exist: $root" }
  }
  if($files.Count -lt 1) { throw 'Day24 LF assertion selected zero files' }
  foreach($file in $files) { $bytes=[IO.File]::ReadAllBytes($file); if([Array]::IndexOf($bytes,[byte]13) -ge 0) { throw "CRLF detected in LF file: $file" } }
}
function Invoke-Day24NodeTest([string]$Path) {
  $output = & node --test $Path 2>&1
  $tap=$output -join "`n"
  $pass=[regex]::Match($tap,'(?m)^# pass ([0-9]+)$')
  $fail=[regex]::Match($tap,'(?m)^# fail ([0-9]+)$')
  $cancelled=[regex]::Match($tap,'(?m)^# cancelled ([0-9]+)$')
  $todo=[regex]::Match($tap,'(?m)^# todo ([0-9]+)$')
  if($LASTEXITCODE -ne 0 -or -not $pass.Success -or -not $fail.Success -or -not $cancelled.Success -or [int]$pass.Groups[1].Value -lt 1 -or [int]$fail.Groups[1].Value -ne 0 -or [int]$cancelled.Groups[1].Value -ne 0 -or ($todo.Success -and [int]$todo.Groups[1].Value -ne 0)) { throw "Node test must report TAP pass >=1, fail 0, cancelled 0, and todo 0: $Path" }
}
function Invoke-Day24Jest([string]$Config,[string]$Spec,[string]$Pattern,[string]$Name) {
  $json=Join-Path ([IO.Path]::GetTempPath()) ("vr24-jest-$Name-"+[guid]::NewGuid()+'.json')
  npx jest --config $Config --runInBand --ci --passWithNoTests=false --runTestsByPath $Spec --testNamePattern $Pattern --json --outputFile $json
  if($LASTEXITCODE -ne 0) { throw "Jest failed: $Name" }
  if(-not (Test-Path -LiteralPath $json)) { throw "Jest produced no JSON: $Name" }
  $result=Get-Content -LiteralPath $json -Raw | ConvertFrom-Json
  if([int]$result.numPassedTests -lt 1 -or [int]$result.numFailedTests -ne 0 -or [int]$result.numFailedTestSuites -ne 0 -or ([int]$result.numPendingTests -gt 0) -or ([int]$result.numTodoTests -gt 0) -or $result.wasInterrupted -eq $true) { throw "Jest selected zero tests or had failures/pending/todo: $Name" }
}

## Objective
Day 5 ships the REUSABLE passwordless-account-activation infrastructure plus its first wired consumer. Identity generates a SET_INITIAL_PASSWORD EmailVerificationToken (UUID v4, TTL 48h) when a SYSTEM_ADMIN creates a passwordless admin user, sends the account-created email link, and consumes it via POST /v1/auth/set-initial-password to set the BCrypt (cost 12) password and flip the user PENDING_INITIAL_PASSWORD -> ACTIVE. It adds resend (authenticated OPERATOR_ADMIN action per technical_context_v7:540), the UserDevice FCM token CRUD (POST + DELETE /v1/auth/device-token) with multi-device claim transfer + safe reactivation, the service-to-service GET /internal/v1/users/{userId}/device-tokens for Notification, and the PENDING_INITIAL_PASSWORD login block.

ACCEPTED SCOPE OVERRIDE (Item 1, option B — Day-5 timeline DoD intentionally narrowed): the original Day-5 timeline DoD says Driver/Assistant/OperatorStaff can be created → email link → set password → login (BE_TIMELINE_VU.md:69-77), while technical_context_v7 also defines Driver/Assistant and OPERATOR_STAFF initial-password flows (technical_context_v7:535-541, :1310-1311). Operator-created Driver/Assistant/OperatorStaff CREATION — and their end-to-end login — is explicitly DEFERRED to Day 6; Task 5.6a's forbidden scope bans touching any operator-create handler. ## Contract changes
New REST endpoints (NONE currently documented in VietRide_API_Contract_v1.md; Task 5.6b adds them):
- POST /v1/auth/set-initial-password, body {token, password}; public (no User JWT, caller clicked an email link). Success 200 with data { userId, status: "ACTIVE" }, NO auto-issued token bundle, parity with verify-email (Q2 resolved). Errors: 400 AUTH_INITIAL_PASSWORD_TOKEN_INVALID, 400 AUTH_INITIAL_PASSWORD_TOKEN_EXPIRED (Q1 resolved: 400 per BSOT 5.9, NOT 410), 422 VALIDATION_ERROR (weak/blank password). NO Idempotency-Key (Item 5, not in BSOT 5.6; one-time token consumption, a repeat call hits an already-used/invalid token to 400 AUTH_INITIAL_PASSWORD_TOKEN_INVALID).
- POST /v1/operator/users/{userId}/resend-initial-password; authenticated OPERATOR_ADMIN action invoked from the operator dashboard (Q3 resolved, technical_context_v7:540). Authenticated path on a NEW OperatorUsersController (NOT a public /v1/auth subpath, NOT the SYSTEM_ADMIN-gated /v1/admin/users family). Tenant isolation is mandatory: caller operatorId must be present in the JWT claims and must equal targetUser.OperatorId; cross-operator targets and non-operator-scoped targets (PASSENGER/SYSTEM_ADMIN/null operatorId) return 403 FORBIDDEN. Revokes any active SET_INITIAL_PASSWORD token, issues new (TTL 48h). Errors (Item 6, pinned to EXISTING BSOT 5.9 codes): 401 (anonymous), 403 FORBIDDEN (authenticated non-OPERATOR_ADMIN, missing caller operatorId, cross-operator target, or non-operator-scoped target), 404 RESOURCE_NOT_FOUND (target userId not found), 422 USER_INVALID_STATUS_TRANSITION (target not in PENDING_INITIAL_PASSWORD). No-active-pending-token-to-resend is NOT an error, resend revokes-any-active-then-generates, so absence of a prior token simply yields a fresh one. NO Idempotency-Key (Item 5, not in BSOT 5.6).
- POST /v1/auth/device-token, body {fcmToken, platform}; User JWT; register/upsert with reactivation + claim transfer. Success 200 with data { deviceId, isActive: true }. NO Idempotency-Key (Item 5, not in BSOT 5.6; behavior-idempotent via upsert/reactivate/claim). (technical_context_v7:4808; Q5 resolved, v7/BSOT path adopted over timeline /devices)
- DELETE /v1/auth/device-token, body {fcmToken}; User JWT; soft-deactivate (is_active=false). Success 204 No Content, EMPTY body, NO ApiResponse envelope (Item 7, ADR 0004 Rule 2 explicitly exempts 204). NO Idempotency-Key (Item 5, not in BSOT 5.6; behavior-idempotent via deactivation, a repeat DELETE on an already-inactive/absent token is a no-op 204). (technical_context_v7:4809; docs/adr/0004-api-response-envelope.md Rule 2; Q5 resolved)
- GET /internal/v1/users/{userId}/device-tokens, Internal JWT (service-to-service, NOT via Gateway). 200 with active fcmToken+platform list. (technical_context_v7:4810; BACKEND_SOURCE_OF_TRUTH.md:1657; Q5 resolved)
